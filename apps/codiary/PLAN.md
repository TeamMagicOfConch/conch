# Codiary - 교환 일기 서비스 기획 문서

## 1. 서비스 개요

**Codiary**는 익명 기반의 실시간 교환 일기 웹 서비스입니다.
참여자들이 매일 일기를 쓰고, 랜덤 매칭된 상대의 일기에 답장을 작성하며, 답장에 대한 리뷰(하이라이트 + 코멘트)를 남기는 세션 기반 교류 플랫폼입니다.

### 핵심 가치

- **익명성**: 누가 쓴 일기인지 모른 채 솔직하게 소통
- **구조화된 교류**: 일기 → 답장 → 리뷰의 3단계 흐름
- **실시간 세션**: 관리자가 운영하는 라이브 세션 방식

## 4. 사용자 흐름 (User Flow)

### 4.1 일반 사용자

```
로그인 → 대기실 → 일기 작성 → 답장 작성 → 리뷰 작성 → 완료 → 대기실
  │                                                          │
  └──────────── 캘린더에서 지난 일기 열람 ◄──────────────────────┘
```

### 4.2 관리자

```
로그인 → 관리자 대기실 → 매칭 설정 → 세션 시작 → 세션 모니터링 → 단계 진행
                │                                    │
                ├── 참여자 관리 ─────────────────────┤
                │                                    │
                └────────────── 강제 종료 ◄──────────┘
                                  │
                                  └→ 관리자 대기실 (새 세션 시작 가능)
```

## 5. 주요 화면 구성

### 5.1 로그인 (AuthForm)

- 로고 표시
- 이메일 입력 후 로그인
- 비밀번호 없이 이메일만으로 인증

### 5.2 대기실 (WaitingRoom)

- 현재 참여자 수 표시
- 캘린더 보기 버튼 (지난 일기 열람)
- 로그아웃 버튼
- **하단 광고 영역**: Google AdSense 배너 광고 표시

### 5.3 일기 작성 (DiaryEditor)

- 상단 타이머 (기본 10분)
- 중앙 텍스트 영역 (흰색 배경)
- 하단 글자 수 + 작성 완료 버튼
- 매칭 제약 경고 배너 (해당 시)

### 5.4 답장 작성 (ResponseEditor)

- **2컬럼 레이아웃**
  - 왼쪽: 배정받은 일기 (노란 포스트잇 스타일)
  - 오른쪽: 답장 작성 영역
- 상단 타이머 (기본 5분)
- 빈 답장 제출 가능

### 5.5 리뷰 작성 (ReviewWriting)

- **2컬럼 레이아웃**
  - 왼쪽: 내 일기 (노란 포스트잇)
  - 오른쪽: 받은 답장 (하이라이트 가능)
- 드래그로 텍스트 하이라이트 (토글 방식)
- 코멘트 작성 영역
- 하이라이트 + 코멘트 모두 필수

### 5.6 캘린더 (CalendarView)

- 7열 그리드 (주간 뷰, 최신순)
- 참여 날짜에 체크 아이콘 표시
- 날짜 클릭 시 일기 + 답장 + 하이라이트 상세 보기

### 5.7 관리자 대기실 (AdminWaitingRoom)

- 참여자 카드 그리드 (이름 + 이메일)
- 매칭 설정 / 세션 시작 버튼

### 5.8 매칭 설정 (MatchingConfig)

- 원형 네트워크 다이어그램 (SVG)
- 사용자 간 제외 쌍 토글 (빨간 선)
- 사용자 삭제 기능

### 5.9 세션 관리 (SessionControl)

- 실시간 타이머 + ±30초 조절
- 진행률 바
- 참여자별 완료 상태 카드
- 매칭 시각화 (답장 단계)
- **세션 강제 종료 버튼** (모든 활성 단계에서 접근 가능)
  - 일기 작성(writing), 답변 작성(responding), 리뷰 작성(reviewing) 중 언제든 사용 가능
  - 확인 다이얼로그 후 남은 단계를 모두 건너뛰어 세션을 즉시 completed 상태로 전환
  - 종료 후 관리자 대기실로 자동 이동하여 새 세션 시작 가능

## 6. 세션 라이프사이클

```
[대기] → [일기 작성] → [답장 작성] → [리뷰 작성] → [완료]
waiting    writing      responding    reviewing    completed
           (10분)        (5분)         (5분)
```

| 단계                       | 시간   | 설명                               | 제출 조건                |
| -------------------------- | ------ | ---------------------------------- | ------------------------ |
| **대기 (waiting)**         | 무제한 | 참여자 입장, 관리자 세션 시작 대기 | -                        |
| **일기 작성 (writing)**    | 10분   | 오늘의 일기 작성                   | 수동 제출 필수           |
| **답장 작성 (responding)** | 5분    | 랜덤 매칭된 상대 일기에 답장       | 빈 답장 허용             |
| **리뷰 작성 (reviewing)**  | 5분    | 받은 답장에 하이라이트 + 코멘트    | 하이라이트 + 코멘트 필수 |
| **완료 (completed)**       | -      | 세션 종료, 대기실로 복귀           | -                        |

> **강제 종료**: 관리자는 writing/responding/reviewing 중 어느 단계에서든 세션을 강제 종료할 수 있습니다. `POST /admin/session/next`를 반복 호출하여 completed 상태까지 전진합니다.

## 7. 매칭 시스템

- **1:1 랜덤 매칭**: 각 사용자가 정확히 한 명과 매칭
- **제외 규칙**: 관리자가 특정 쌍을 매칭에서 제외 가능 (예: 친한 사이)
- **시각적 설정**: 원형 네트워크 다이어그램으로 제외 쌍 관리
- **방향성**: A → B (A가 B의 일기에 답장)

## 9. API 구조

### 인증

| 엔드포인트          | 설명             |
| ------------------- | ---------------- |
| `POST /auth/signin` | 이메일 로그인    |
| `GET /auth/session` | 사용자 정보 조회 |

### 세션

| 엔드포인트             | 설명           |
| ---------------------- | -------------- |
| `GET /session/current` | 현재 세션 상태 |
| `POST /session/join`   | 세션 참가      |
| `POST /session/leave`  | 세션 나가기    |

### 일기 / 답장 / 리뷰

| 엔드포인트               | 설명                |
| ------------------------ | ------------------- |
| `POST /diary/write`      | 일기 작성           |
| `GET /diary/assigned`    | 배정된 일기 조회    |
| `GET /diary/history`     | 일기 히스토리       |
| `POST /response/write`   | 답장 작성           |
| `GET /response/my-diary` | 내 일기에 대한 답장 |
| `POST /review/write`     | 리뷰 작성           |

### 관리자

| 엔드포인트                        | 설명             |
| --------------------------------- | ---------------- |
| `POST /admin/session/start`       | 세션 시작        |
| `POST /admin/session/next`        | 다음 단계 진행   |
| `GET /admin/session/statuses`     | 참여자 상태 조회 |
| `POST /admin/session/timer`       | 타이머 조절      |
| `GET /admin/matching/exclusions`  | 매칭 제외 목록   |
| `POST /admin/matching/exclusions` | 매칭 제외 설정   |
| `DELETE /admin/user/delete`       | 사용자 삭제      |

## 13. 광고 (Google AdSense)

### 적용 위치

- **대기실 (WaitingRoom)**: 하단 영역에 배너 광고 표시
  - 기존 앱 다운로드 프로모션 영역을 AdSense 광고로 대체

### AdSense 설정

- **퍼블리셔 ID**: `ca-pub-4077089301782274`
- **스크립트**: `https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js`
- **광고 형태**: 반응형 배너 (대기실 카드 영역에 맞춤)

### 구현 방식

- `index.html`에 AdSense 스크립트 태그 추가
- 대기실 컴포넌트에 `<ins class="adsbygoogle">` 광고 슬롯 삽입
- 대기 중 사용자에게 자연스럽게 노출
